# Сильное сжатие (экспериментально)

Для случаев, когда нужен не «аккуратный» результат, а очень маленький файл: например, ролик в 1 ГБ
уложить в 10 МБ ценой разрешения, частоты кадров, цвета и качества звука. Блок
**Advanced ▸ Strong compression (experimental)** в Windows-версии (с 0.6.0); для macOS это
задание (раздел «Для macOS» ниже). Только для видео: не для фото, GIF и режимов «только звук».

Связано: [docs/QUALITY.md](QUALITY.md) · [Windows/README.md](../Windows/README.md) · [CHANGELOG.md](../CHANGELOG.md)

## Что можно задать

| Настройка | Значения | Что делает (FFmpeg) |
|---|---|---|
| Видеокодек | Стандартный (H.264 / VP9), **AV1** (SVT-AV1), **HEVC** (x265), **H.266 / VVC** (vvenc, очень медленно) | `libsvtav1 -preset 6`, `libx265 -preset medium`, `libvvenc -preset medium -pix_fmt yuv420p10le` |
| Уложить в N МБ | от 0,05 МБ | битрейт по длительности, до 4 полных проходов (см. ниже) |
| Длинная сторона | до 320 px | `scale=W:H:flags=lanczos`, только вниз |
| Кадров/с | 6, 10, 12, 15… | `fps=N`, только вниз |
| Звук | как обычно / моно 32 / 16 / 8 кбит/с | первая дорожка, `libopus -b:a Nk -ac 1` (`-application voip` при ≤ 24 кбит/с) |
| Чёрно-белое | флажок | `hue=s=0` (цветность становится почти бесплатной) |
| Убрать шум | флажок | `hqdn3d=3:2:6:4` |
| Пропускать повторы кадров | флажок | `mpdecimate` и `-fps_mode vfr` |

Порядок фильтров всегда такой: `fps` → `scale` → `setsar` → `hqdn3d` → `hue` → `mpdecimate`
(сначала уменьшаем, потом чистим уже маленькие кадры).

**Шаблоны** («Сильное», «Максимальное», «Предельное») только выставляют эти настройки, их можно
поправить: длинная сторона 640 / 480 / 320 px, кадры 15 / 10 / 6, звук моно 32 / 16 / 8 кбит/с,
качество Среднее / Приемлемое / Приемлемое, «Убрать шум» и «Пропускать повторы» включены.

## Контейнеры

AV1 → `.mp4` (или `.webm`, если выбран WebM; `.mkv`, если исходник `.mkv`), HEVC → `.mp4` с меткой
`hvc1` (или `.mkv`), VVC → всегда `.mkv`. HEVC и VVC в WebM не кладутся: сообщение об ошибке.
Видео с прозрачностью — только стандартным кодеком в WebM (VP9). Opus в MP4 и AV1/VVC могут не
открываться в старых плеерах; интерфейс предупреждает об этом.

## Целевой размер: как подбирается битрейт

1. Бюджет в битах: `N МБ × 1048576 × 8 × 0,95` (5 % на контейнер и округление), делим на длительность.
2. Звук: заданный битрейт или, если задан только размер, около 8 % бюджета, от 16 до 96 кбит/с
   (до 32 кбит/с — моно). Видеобитрейт = `(бюджет − звук) × 0,92`: первая попытка идёт с запасом,
   потому что при малых битрейтах кодеры превышают заданное.
3. Меньше 20 кбит/с на видео — отказ с понятным сообщением, сколько МБ нужно хотя бы.
4. Кодируем одним проходом (ABR/VBR: `-b:v`, у x264 и x265 ещё `-maxrate` / `-bufsize`).
   Если файл вышел больше цели, следующий битрейт = `битрейт × (цель / получилось)^1,25 × 0,94`
   (поправка круче простой пропорции, потому что превышение растёт при малых битрейтах).
   Всего до **4** попыток; если не вышло — ошибка «Could not fit into N MB: got M MB» с советом
   уменьшить разрешение или частоту кадров. Файл меньше цели — нормально.
5. Длительность должна быть известна (иначе отказ). Прогресс на повторе начинается заново.
6. Затем обычные проверки: размеры, длительность, и результат не заменяет исходник, если не меньше него.

Что намеренно **не** делается: удаление фона и прочие приёмы с нейросетями: у FFmpeg их нет
офлайн-стандартными средствами. Остальное («потерять фон» в смысле детализации) достигается
шумоподавлением, понижением разрешения и качества.

## Проверки

Движок: `Windows/Vacpack.Tests/Program.cs` (сборка аргументов, расчёт битрейта, отказы) и,
если FFmpeg умеет `libsvtav1`, `libx265`, `libvvenc`, реальные кодирования: AV1 и HEVC укладываются в
0,3 МБ на короткий ролик, стандартный кодек с целью 0,08 МБ даёт 160×120, ≤ 10 кадров/с и одну
дорожку Opus, VVC кодирует в Matroska. Запуск: `.\scripts\windows.ps1 -Mode check`.

## Для macOS (задание)

В Swift-пакете `CompressorKit` (`Engines/Video/VideoCommand.swift`, `VideoEngine.swift`,
`Model/VideoSettings.swift`) добавить те же поля настроек и тот же расчёт, а в `ContentView.swift`
вложенный блок в строке видео. Использовать правила и числа из этого файла и тесты из
`Windows/Vacpack.Tests/Program.cs` как эталон (перенести в `Packages/CompressorKit/Tests`).
Особенности Mac: те же утилиты Homebrew (`brew install ffmpeg` содержит SVT-AV1 и x265; vvenc
может отсутствовать: тогда пункт H.266 недоступен, определять по `ffmpeg -encoders`), аппаратный
кодер VideoToolbox для этого режима не использовать (он не держит заданный битрейт). Строки
интерфейса — в `App/Resources/Localizable.xcstrings`. Собрать и проверить `scripts/check.sh`.
