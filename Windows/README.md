# Vacpack для Windows — эксперимент

Первый рабочий Windows-прототип в ветке `codex/experimental-platform-support`.
Нативное окно WPF / .NET 8 и отдельный движок `Vacpack.Core`, который запускает
FFmpeg и ffprobe без shell. Все файлы обрабатываются локально.

Интерфейс сохраняет иконку и горчично-охристую палитру macOS-версии. Swift-код и
сборка Xcode продолжают жить в прежних каталогах. Версия Windows читается при
сборке из `project.yml`; менять её отдельно не нужно.

## Запуск из исходников

Нужны Windows 10/11, [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)
и Windows-сборка [FFmpeg](https://ffmpeg.org/download.html#build-windows) с
`ffmpeg.exe`, `ffprobe.exe` и кодеками libx264, libvpx-vp9, libwebp, libaom-av1,
AAC, libmp3lame и libopus. HEIC и SVG в этом прототипе не принимаются.

В PowerShell из корня репозитория:

```powershell
.\scripts\windows.ps1 -Mode run -ToolsDirectory 'C:\ffmpeg\bin'
```

Путь к инструментам можно вместо этого задать переменной `VACPACK_TOOLS` или
выбрать в окне приложения. Поиск идёт в таком порядке: `VACPACK_TOOLS`, `tools`
рядом с EXE, `%LOCALAPPDATA%\Vacpack\tools`, абсолютные каталоги из `PATH`,
затем `scoop\apps\ffmpeg\current\bin` в `%USERPROFILE%` (либо относительно `SCOOP`).
Выбранная в окне папка действует до закрытия приложения.

## Что работает

- Добавление файлов, папок с подпапками и перетаскивание из Проводника.
- Фото: JPEG, PNG, WebP, AVIF, TIFF, BMP; вывод в исходный формат, JPEG, PNG,
  WebP, AVIF. Прозрачность в PNG/WebP сохраняется, в JPEG заменяется белым.
- Видео: MP4, MOV, MKV, WebM, AVI, M4V, MPEG, MTS, M2TS, WMV на входе;
  MP4/MOV/MKV с H.264 или WebM с VP9 на выходе. Выбор «Как в исходнике»
  сохраняет MOV/MKV/WebM, остальные контейнеры переводит в MP4.
- Все звуковые дорожки видео сохраняются; несовместимые с контейнером
  перекодируются. Можно полностью убрать звук.
- Извлечение первой звуковой дорожки в M4A, MP3, Opus; профиль речи — моно,
  выравнивание громкости, сниженный битрейт.
- GIF → GIF и видео → GIF с палитрой FFmpeg, уменьшением размера и лимитом fps.
- Пять уровней качества, ограничение длинной стороны и fps без увеличения.
- Последовательная очередь, прогресс, остановка всего дерева процессов,
  продолжение оставшихся файлов и повтор со сменой настроек.
- Сохранение рядом с исходником или в выбранную папку. Имена `имя-vacpack.ext`,
  `имя-vacpack (1).ext` и далее; существующие файлы не перезаписываются.
- Проверка результата через ffprobe: размер, геометрия, длительность и
  прозрачность. Если файл не стал меньше, временный результат удаляется.
  Исходники не удаляются и не перемещаются. Можно сохранить даты файлов.
- Двойной щелчок открывает папку файла в Проводнике; Delete убирает выбранные
  строки из очереди, не удаляя файлы с диска.

Интерфейс показывает настройки для типов файлов в очереди: например, для одного
видео блок фото скрыт, а профиль речи появляется при выборе звукового формата.
Выбор папки вывода закреплён внизу панели. У строк есть кнопки открытия папки и
удаления из списка; ошибки открываются кнопкой «Подробнее». Полоса прогресса
видна только во время работы. После завершения кнопка «Сжать снова» повторяет
обработку с текущими настройками. Ctrl+O добавляет файлы, Ctrl+Enter запускает
сжатие, Esc останавливает текущую обработку.

## Ограничения эксперимента

Это отдельная реализация движка; Swift `CompressorKit` использует ImageIO,
AppKit и AVFoundation и пока не переносился на Windows. Параметры H.264/VP9,
потолок битрейта и уровни WebP перенесены из его таблиц, но побайтового
совпадения результатов между платформами нет.

Пока нет HEIC/HEIF, DNG, SVG, APNG, PDF/EPUB, целевого размера, HEVC, аппаратного
ускорения, обложек звуковых файлов, системного Share, предпросмотра, тёмной темы
и сохранения настроек между запусками. GIF использует FFmpeg вместо gifski;
PNG сжимается без потерь и без pngquant, поэтому уровень качества на PNG не
влияет. Метаданные EXIF/IPTC/XMP/ICC и Finder-теги не переносятся; даты файлов
сохраняются отдельно. Для AVIF с прозрачностью нужно выбрать PNG или WebP.

HDR определяется и отклоняется, чтобы не выдавать некорректный цвет. Для
определяемого прозрачного видео поддерживается WebM. HEVC с отдельным слоем
альфы в MOV требует Apple API и на Windows не поддерживается. Некоторые
входные форматы/кодеки зависят от установленной сборки FFmpeg. ARM64-сборка и
запуск на чистой Windows 10 пока не проверены.

## Проверки

```powershell
.\scripts\windows.ps1 -Mode check -ToolsDirectory 'C:\ffmpeg\bin' -RequireMediaTests
```

Проверки — исполняемый консольный проект без NuGet-зависимостей: реальные
процессы, отмена дерева процессов, таймауты, Unicode/пробелы в аргументах,
коллизии имён, сохранность оригинала, прозрачность и белая подложка JPEG,
несколько звуковых дорожек, длительность GIF/видео/аудио. Медиафайлы генерируются
в `.build/windows-tests/`. Без FFmpeg интеграционные проверки явно пропускаются;
`-RequireMediaTests` превращает такой пропуск в ошибку. WPF собирается с
предупреждениями как ошибками; скрипт также скрыто запускает окно с заполненной
очередью и сохраняет снимок в `.build/windows-ui-check.png`, проверяя отложенные
ошибки привязок. Для этого нужен доступ к рабочему столу Windows.

```powershell
$env:VACPACK_TOOLS = 'C:\ffmpeg\bin'
Windows\Vacpack.Windows\bin\Debug\net8.0-windows\Vacpack.exe --snapshot C:\temp\vacpack.png
# Сжать перед снимком, используя текущие настройки по умолчанию:
Windows\Vacpack.Windows\bin\Debug\net8.0-windows\Vacpack.exe --snapshot C:\temp\results.png --compress C:\temp\photo.png C:\temp\clip.mp4
```

## Сборка для запуска

```powershell
.\scripts\windows.ps1 -Mode package
```

Результат: `.build/windows/Vacpack/Vacpack.exe` и соседние файлы. Переносить
нужно всю папку. Сборка self-contained (win-x64): среда .NET 8 входит в папку,
отдельно ставить Runtime не нужно. Подпись пока не сделана.
FFmpeg устанавливается отдельно; бинарники кодеров не включаются в сборку.
Приложение — GPL-3.0; текст `LICENSE` лежит рядом с EXE.

Для self-contained публикации скрипт скачивает runtime-пакеты win-x64 с nuget.org
(`Windows/NuGet.Publish.Config`); обычные `check` и `run` по-прежнему работают
без сети.

## Установщик

```powershell
.\scripts\windows.ps1 -Mode installer
```

Нужен [Inno Setup 6](https://jrsoftware.org/isdl.php). Скрипт публикует
приложение в `.build/windows/installer-staging` и собирает
`.build/windows/Vacpack-Setup-<версия>.exe` по `Windows/installer/Vacpack.iss`.
Версия берётся из `project.yml`. Установщик ставит приложение в профиль
пользователя (права администратора не нужны), создаёт ярлык в меню «Пуск»,
по желанию на рабочем столе, и деинсталлятор. FFmpeg по-прежнему ставится отдельно.

Чтобы собрать новое окно для сравнения с уже запущенной версией:

```powershell
.\scripts\windows.ps1 -Mode package -DestinationDirectory .build\windows\Vacpack-preview
```

## Дальнейшее направление

Сначала сравнить прототип на реальных пользовательских файлах с macOS-версией.
Если Windows-ветка подходит, следующий шаг — вынести общие таблицы параметров
в платформонезависимый формат с тестами соответствия, добавить перенос
метаданных и проверяемую поставку кодеров, затем установщик и CI на Windows.
